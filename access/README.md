# Рабочий доступ для проверки

Клиентский профиль к развёрнутому стенду — для проверки работы туннеля из РФ
(пункт «Рабочий доступ для проверки» тестового задания).

| | |
|---|---|
| Сервер | `5.129.239.130:443` (Amsterdam, Timeweb) |
| Протокол | VLESS + XTLS-Reality, flow `xtls-rprx-vision` |
| Домен-маскировка (SNI) | `www.nvidia.com` |
| Клиенты | Hiddify, v2rayNG, Streisand |

## Как подключиться

1. **Ссылкой:** скопировать строку из [`client-link.txt`](client-link.txt) и
   импортировать в клиент («Импорт из буфера обмена»).
2. **QR-кодом:** отсканировать [`client-qr.png`](client-qr.png) камерой в приложении.

Оба файла описывают один и тот же профиль: QR сгенерирован из этой же ссылки
(проверено пересборкой — контрольные суммы совпадают).

## Важно

- Это **временные креды тестового стенда**, выложенные открыто ради удобства
  проверки. Они не ведут ни к какой продакшен-инфраструктуре.
- Сервер держится активным **7 дней** после сдачи отчёта.
- После проверки ключи ротируются одной командой — `./deploy.sh --regen` на сервере
  (генерирует новые UUID, x25519-пару и shortId; старая ссылка перестаёт работать).
- В обычном режиме работы эти артефакты в git **не попадают**: `deploy.sh` создаёт их
  в корне проекта, а корневые `client-link.txt` / `client-qr.png` закрыты `.gitignore`.
  Здесь лежит осознанно положенная копия.
